# Decisions

| ID | Date | Decision | Why |
|---|---|---|---|
| D001 | 2026-09-16 | Drop SRE/NOC as the product. Skanyxx is a licensed **agent management workspace**. | Customer value is building agents, skills, MCP, and company knowledge — not watching incidents. |
| D002 | 2026-09-16 | **KAgent stays the runtime** that connects the customer’s models to agents. Skanyxx does not replace kagent. | That path already works; kagent is the Kubernetes-native agent platform ([docs](https://kagent.dev/docs/kagent/)). |
| D003 | 2026-09-16 | **One install per customer.** | Isolation of people, models, agents, and memory. Not a shared multi-tenant cloud. |
| D004 | 2026-09-16 | **One UI, three roles** (owner, builder, employee). Any of them can be the first user. | Same product; home/permissions change with role. Not three apps. |
| D005 | 2026-09-16 | Community of templates is **planned and urgent**, but shares **recipes only** (agent / skill / MCP). Never customer memory. | Need a catalog path soon; company knowledge is the customer’s IP. |
| D006 | 2026-09-16 | Company memory is a **governed engine**, not “record into one agent.” Intake can be any work (chat, files, meetings, tickets, voice, agent runs). | Recording was only an example. Knowledge must be reusable across relevant agents. |
| D007 | 2026-09-16 | People contribute to **collections**; builders **grant collections to agents**. | Aggregation without dumping the whole company brain into every bot. |
| D008 | 2026-09-16 | Do **not** treat kagent’s built-in agent memory as the company memory bank. | kagent memory is per-agent, TTL (default 15 days), **no cross-agent sharing** ([agent memory](https://kagent.dev/docs/kagent/concepts/agent-memory/)). kagent itself says a company store should come in as **MCP**. |
| D009 | 2026-09-16 | People can **search and open** memory items in Skanyxx. This is a knowledge library, **not a file explorer**. Daily use is still mostly through agents. | Later someone must read *what* we did and *why* without guessing. A folder tree of files is the wrong metaphor. |
| D010 | 2026-09-16 | Agents **may write** into company memory when they have that skill and collection grant. They write structured items (decision / fact / open), not raw chat logs. | Example: this design thread. If Skanyxx-agent had been the partner, the bank would already hold D001–D011 so a future person (or agent) can recover the trail. |
| D011 | 2026-09-16 | Publish policy is **per collection** (and by agent trust). No single global “always review” or “always auto”. | Legal/HR may need a queue. A trusted design-agent writing to `skanyxx-design` may auto-publish. |
| D012 | 2026-09-16 | **Sessions are not memory.** Chat/work logs are ephemeral (or a separate audit store with short TTL). The bank only keeps extracted items. | Logging every employee×agent turn would explode storage. Memory is “what/why we locked,” not the conversation. |
| D013 | 2026-09-16 | Agents **never read the bank**. They **search** granted collections and get **top-k** small cards into context. | Re-feeding stored text every turn would burn tokens and still miss the point. Retrieval, not reread. |
| D014 | 2026-09-16 | Three layers: **card** (tiny, for search+prompt), **body** (optional, for a human opening the item), **source** (blob/URL, never inlined into the agent). | Recordings, PDFs, transcripts stay cheap object storage. Prompts only see the card. |
| D015 | 2026-09-16 | Same fact is **updated or superseded**, not appended forever. | Stops duplicate “we use kagent” items from filling the index and the prompt. |
| D016 | 2026-09-16 | Three planes: **Skanyxx** = workspace, **kagent** = runtime, **memory engine** = company knowledge via MCP. | Mixing them causes a fake SRE console, token reread, or treating kagent TTL memory as the company brain. See `three-planes.md`. |
| D017 | 2026-09-16 | People talk to agents **only in Skanyxx chat** (day one). Slack / IDE / kagent UI are not the conversation surface. | Chat is the product. kagent UI stays an ops detail of the runtime. |
| D018 | 2026-09-16 | The license **includes our setup**: we install Skanyxx + kagent (+ memory) on the customer’s side. They do not bring their own kagent. | One working stack per customer. Owner should not assemble the three planes by hand. |
| D019 | 2026-09-16 | **Start clean.** Do not ship kagent’s sample agent pack. Ship **one general-purpose agent** wired to the configured model + memory MCP + `company` collection. It is the seed of the ecosystem, not a fleet. | Production should not look like a demo cluster. One talker starts filling memory so later (studio) agents have soil. |
| D020 | 2026-09-16 | Factory is **builder sugar**: propose kagent YAML via chat. It becomes live **only after a git PR is merged**. Studio edits the same files. | Agents are YAML. PR is the approval mechanism. Prevents a silent fleet from one chat. |
| D021 | 2026-09-16 | **Memory cards never use PRs.** Only agent/MCP/skill/grant definitions do. | Card volume would spam git and is a different lifecycle (D012). |
| D022 | 2026-09-16 | Factory tools are for **builder/dev roles**, not employees talking to the seed agent. | Employees grow knowledge. Builders (with review) grow the fleet. |
| D023 | 2026-09-16 | **We create** the agent-config repo as part of setup. If they give GitHub/GitLab, create it there. If not, bundle git in the stack. Pointing at an existing repo is an **owner option later**, not day one. | First hour cannot depend on a GitOps shop already existing. Real orgs can attach their monorepo later. |
| D024 | 2026-09-16 | **Agent supervisor** merges agent PRs (the approval). Builders open PRs; they cannot make an agent live alone. Small orgs: owner also wears supervisor. | Dedicated responsibility, not “any builder” and not “only the CEO title”. |
| D025 | 2026-09-16 | **First login is the owner** created by setup. They configure (model, git if needed) and **add users**. Nobody else exists until they do. | One named person must jump in. Chat and cards need identity. |
| D026 | 2026-09-16 | Adding users: **invite always works**. Optional directory (**Entra ID** first) after first login — not a setup blocker. | Many customers have Entra; many do not. First hour cannot wait on SSO. |
| D027 | 2026-09-16 | Directory does **not** dump the whole tenant in. Owner maps IdP **groups → Skanyxx roles**. Unmapped people have no access. | A company memory bank is not a public Slack. Accidental 10k employees is worse than a slow invite. |
| D028 | 2026-09-16 | **Studio** is a composer form over the agent-config git repo. Save opens a PR. It is not live-apply and not kagent’s UI. | Same source of truth as factory (D020). Supervisor still the gate (D024). |
| D029 | 2026-09-16 | An agent in studio is: **name + model + instructions + skills + MCP tools + collection grants** (+ optional kagent TTL memory). | That is the kagent Agent CR plus Skanyxx grants. Community templates later fill these slots, they are not extra slots. |
| D030 | 2026-09-16 | Builders (and supervisor) get **Preview chat** on the PR/branch sandbox. | Otherwise every prompt typo needs a merge. |
| D031 | 2026-09-16 | **Employees** only see **merged** agents in Skanyxx chat. Drafts are not in the company fleet. | Supervisor owns what the company talks to. |
| D032 | 2026-09-16 | Preview may **search** production collections; it must **not upsert** cards into them. | A draft agent must not pollute the company bank. |
| D033 | 2026-09-16 | Per collection, two grants: **search** and **upsert**. An agent can have search without upsert. | A FAQ agent may read `billing` and must not write it. |
| D034 | 2026-09-16 | A memory **card** is: `collection`+`key`, `type`, `what`, `why`, `who`, `when`, `status`; `body` and `source` stay off the default prompt. | Tiny on purpose. See `memory-card.md`. |
| D035 | 2026-09-16 | Upsert identity is **`collection` + `key`** (e.g. `billing/refund-window`). Same key overwrites; it does not append. | D015 needs a name, not fuzzy “looks similar.” |
| D036 | 2026-09-16 | Card types are only **decision, fact, procedure, open**. | More types become a dumping ground. Media is `source`, not a type. |
| D037 | 2026-09-16 | Hard caps: `what` 200 chars, `why` 400 chars. Default retrieve **top-5 published** cards. | Token budget is a product rule, not a hope. |
| D038 | 2026-09-16 | Agent **proposes** `key`; a human may rename it in the library. | Slugs must be machine-usable and still fixable. |
| D039 | 2026-09-16 | Day one only one collection: **`company`**. No per-user `private` yet. | Clean start. More collections when a builder/supervisor adds them. |
| D040 | 2026-09-16 | New agents default to **search** on `company`, **not upsert**. Write is an explicit grant. | 100 agents must not all stamp the bank. Storm is a permission problem first. |
| D041 | 2026-09-16 | Writes go through the **memory engine**, serialized per `collection/key`, with a **version**. Stale version = conflict (agent re-reads). No silent last-write-wins. | Two agents editing the same fact must not clobber without noticing. |
| D042 | 2026-09-16 | **Do not orchestrate agents with Redis/Dragonfly.** Optional later: cache + distributed lock **inside** the memory service. Source of truth stays the memory store. | Redis is not a fleet brain. kagent runs agents; the bank coordinates **keys**. |
| D043 | 2026-09-16 | When the memory service needs a cache/lock (multi-replica, hot reads), use **Dragonfly**. | Named later; not in the first-hour stack. Same role as D042’s “optional.” |
| D044 | 2026-09-16 | Chat **transcripts** default TTL **14 days** (owner-configurable). Memory **cards** are not on that TTL. | Sessions are not the bank (D012). Cards live until superseded/policy. |
| D045 | 2026-09-16 | Merged agent YAML is applied by **our reconciler** to kagent. Flux/Argo may replace that later. | We provide the setup (D018). Day one is not “please install Argo.” |
| D046 | 2026-09-16 | Company memory is a **Skanyxx engine** (MCP to kagent). **Not Joicy** as the store. | Joicy is code/git-shaped; we need collections, version, grants. Keep Joicy as sister. |
| D047 | 2026-09-16 | Production setup target is the **customer’s Kubernetes** (Helm/installer deploys the three planes + git). | kagent is k8s-native. One stack per customer. |
| D048 | 2026-09-16 | Day-one **library**: logged-in users can open **published `company`** cards. That is independent of agent grants. | Humans audit the trail (D009). Agents still need search/upsert (D033). |
| D049 | 2026-09-16 | Memory scopes: **personal → team → department → company**. D039 (only `company`) is superseded. | Knowledge is born in private chats; the product is **lift**, not one pile. See `memory-hierarchy.md`. |
| D050 | 2026-09-16 | Chat history stays **personal**. We lift **cards**, never the transcript, to team/dept/company. | Same volume rule as D012. Fix silos without cloning every DM. |
| D051 | 2026-09-16 | Promote **copies up**. The author’s personal card remains. | Higher layer can supersede without erasing origin. |
| D052 | 2026-09-16 | Seed/employee **upsert defaults to personal**. Company search stays the default grant for new agents. Lift into **company** needs supervisor/owner; into **team** needs a team member. | Stops 100 agents publishing maniacally to the company brain. |
| D053 | 2026-09-16 | Memory stack: **Postgres** (cards, sessions, FTS, versions) + **S3/MinIO** (blobs) + MCP service. **Dragonfly** later. **pgvector** later. Not Joicy. | Durable source of truth on k8s. See `memory-stack.md`. |
| D054 | 2026-09-16 | **Community catalog paused.** | Memory hierarchy and stack first. |
| D055 | 2026-09-16 | **Org tree lives in Skanyxx** (people, teams, departments). Entra/Google/Okta are optional **mappers**, not required. No Azure → owner builds the tree by invite. | Hierarchy cannot wait on SSO. Azure is one customer, not the product. |
| D056 | 2026-09-16 | License → owner runs **our installer once**. UI is the **browser URL**. Invited users open that URL. They do not install per-user apps. | Chat is a website. See `install-path.md`. |
| D057 | 2026-09-16 | Two install modes: **appliance** (Linux VM / marketplace; we embed k3s, they never see k8s) and **bring-your-cluster** (Helm). Same workloads. | kagent needs k8s. Most buyers should not have to know what that is. |
| D058 | 2026-09-16 | **Skanyxx (UI + control plane) is separate from kagent.** It **configures controller URLs** (kagent, memory MCP) as today. Default appliance/Helm colocates them. Split is supported. | Matches current Skanyxx. k8s is for the runtime, not a requirement for where the browser app runs. |
| D059 | 2026-09-16 | A **downloadable desktop client** is allowed (UI like today). It calls **shared** kagent + **shared** Skanyxx/memory URLs. It must **not** keep the company user DB, org tree, or lifted cards only on that laptop. | Today’s one-operator local backend does not scale to a company bank. Client vs source of truth. |
| D060 | 2026-09-16 | The **product we ship** is a **Helm umbrella** (Skanyxx API, kagent, memory, Postgres, MinIO, git). Today’s fat local Skanyxx **thins** to a browser/desktop **client** of that umbrella. | Company brain is the cluster chart. The Windows build is not the source of truth. |
| D061 | 2026-09-16 | Umbrella **bundles** Postgres, MinIO, and git **on by default**. Helm values can **turn each off** and point at the customer’s own (RDS/Cloud SQL, S3/Azure Blob, GitHub/GitLab). | Appliance works with zero extra accounts. Platform teams keep their existing data stores. |
